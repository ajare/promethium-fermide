# Decompose World's remaining responsibilities into owned collaborators

Status: accepted

Even after ADR 0004 moved simulation coordination into `SimulationCoordinator`, `src/core/World.cpp` is still ~13,600 lines with 487 `World::` methods and `include/core/World.h` ~3,500 lines. What remains is a set of unrelated jobs sharing one class: authoring topology, placement validation, permissions and access grants, Agent tag assignment and sampled properties, per-Agent individual overrides, markers, furniture, traversal-resource creation, device condition, and registry attach/detach. We decide to **continue the ADR 0004 pattern rather than invent a new one**: each cohesive responsibility becomes a named collaborator class owned by `World`; `World` keeps ownership of every entity registry per ADR 0001 and stays the facade (the design pattern — not the Facade sector of CONTEXT.md) through which all callers reach the collaborators; and each collaborator's implementation is split per seam behind a single header, following the `SimulationCoordinator*.cpp` precedent. Two cross-cutting templates collapse the largest duplication before the bulk of the behaviour moves.

## Considered options

- **Stop at ADR 0004 and leave the rest in `World`.** Rejected: the translation-unit and header-size problem that motivated 0004 is only half solved; the remaining 487 methods still mix authoring, validation, authorization, and per-Agent property management in one class, so the next reader still cannot find a responsibility's boundary.
- **File-split only (`WorldAuthoring.cpp`, `WorldPermissions.cpp`, …), same class.** Rejected for the same reason 0004 rejected it: it shrinks the source but leaves the ~3,500-line header and keeps unrelated responsibilities in one type. Named collaborators cost little more and give each seam a real boundary and a unit-testable surface.
- **Pimpl behind `World`.** Rejected: hides the collaborators, makes them untestable in isolation, and adds indirection with no consumer that needs the opacity.
- **Move the entity registries into the collaborators.** Rejected: contradicts ADR 0001 ("World owns simulation entities") and would drag serialisation and construction-record replay along for no behavioural gain. Collaborators operate on World-owned state; they do not take ownership of the registries.
- **One big-bang decomposition.** Rejected: thousands of lines moving at once is unreviewable. The work proceeds staged and leaf-first (see Consequences) so every stage compiles against a `World` that still owns the rest, builds green in Release, and passes the headless smoke test before the next move.
- **Model every repetitive family as its own full class.** Rejected for the two largest families in favour of templates (see Consequences): the per-property and per-registry families differ only by type and clamp, so a descriptor/template collapses them to one code path instead of duplicating the God-object shape inside a new class.

## Consequences

- **Planned seams.** `AuthorizationLedger` (AccessPermission + PermissionSet CRUD, Agent grant/assignment) and `PermissionRequirementStore` (the `*PermissionRequirement` get/set over `mPendingPermissionRequirements` / `mAuthoredControlRequirements`); `AgentTagService` (assign/remove/reconcile/validate/inspect); `AgentProfileEditor` (the `setAgentIndividual*` overrides); `AgentGroupRegistry`; `AgentTypeCatalog`; `MarkerStore`; `PlacementValidator` (the read-only `validate*` family and `dimensionsAreSupported`); `WorldBuilder`, split by structure (`…Sectors`, `…Doors`, `…VerticalTransit`, `…SectorObjects`); `TraversalResourceRegistry`; `FurnitureStore`; and `DeviceConditionStore` (authored/runtime Broken state). Exact seam boundaries are refined per leaf; the list is the target shape, not a fixed contract.
- **Two de-duplication templates land before the bulk moves.** A `RegistryBinding<T>` collapses the near-identical AgentTag and AgentBehaviour attach/detach/resolve/replace/has/get families (~23 methods) into one parameterised binding over the registry type plus its resource-name/UUID pair. A property-descriptor table collapses the ~26 `setAgentIndividual*` and ~26 `addAgentTag*Samples` / `clearAgentTag*Samples` methods, which differ only by property type and clamp, into a single setter path — making ADR 0012's "individual properties override tag properties" rule one code path rather than dozens.
- **Naming.** Collaborators are named *coordinator / registry / store / service / catalog*. "Controller" is not used: CONTEXT.md bans "Device controller" and "traversal controller". Docs and comments write "facade (design pattern)" or "World remains the facade" in full, to avoid collision with the Facade sector type.
- **Access seam.** Collaborators need access to World-owned state; like `SimulationCoordinator` they are granted `friend` access (or a narrow accessor seam) rather than forcing every registry public. Tightening that encapsulation is a separate, later decision.
- **Serialisation and replay are untouched.** `WorldSerialization.cpp` and construction-record replay do not move: behaviour moves out of `World`, state does not. `World` continues to own sectors, layers, the graph, and every entity registry per ADR 0001 and the aggregate name per ADR 0009.
- **Runtime eligibility stays thin.** The `canAgent…Now` checks that read live graph/geometry and traversal state remain as `World`/`SimulationCoordinator` forwards rather than being forced into `AuthorizationLedger`; the ledger holds authorization facts, not live traversal evaluation. This keeps ADR 0015 ("authorize control operation rather than resource passage") and ADR 0013 (terminal-record retirement) intact.
- **Staged order (leaf-first).** (1) read-only/clean leaves — `PlacementValidator`, `AgentGroupRegistry`, `AgentTypeCatalog`, `MarkerStore`; (2) the two templates; (3) `AgentTagService` and `AgentProfileEditor` on top of the templates; (4) `AuthorizationLedger` + `PermissionRequirementStore`; (5) `WorldBuilder` + `TraversalResourceRegistry` last, as they are most entangled with construction-record replay. Each stage: extract → `World` forwards → Release build green → headless smoke passes, before the next.
- **What stays on `World`.** Identity/dimension accessors, level/layer naming, sector/layer/graph ownership, the simulation facade already forwarding to `SimulationCoordinator`, and the edit-plan / construction-record orchestration that stitches the collaborators together. The end state is a `World` that owns and forwards rather than implements.
