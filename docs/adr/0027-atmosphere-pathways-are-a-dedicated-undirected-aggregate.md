# Atmosphere pathways are a dedicated undirected aggregate, not Station connections

Status: accepted

A pathway between two Atmosphere compartments had to be authored somewhere. The obvious host was the existing Station connection catalogue, which already carries `Medium::Atmosphere`, already maps to a physical type, and already gives the editor and diagram a place to put things. We decided against it and gave pathways their own undirected aggregate, for reasons that are not visible in the schema and would otherwise be quietly undone.

**The existing connection properties do not describe a pathway.** `StationConnectionProperties` carries a physical type, a maximum throughput, and an efficiency. A pathway needs an area and an openness. None of the three existing fields means anything here: the area *is* the capacity, so there is no separate throughput ceiling; and nothing is lost in transit, so there is no efficiency. Meaningful-but-inapplicable fields are the hazard — a later change that wires `efficiency` into a diffusive flow would make mass vanish through a field that was never meant to be read there.

**Directedness would double-count the opening.** The connection key is a directed relationship. A pathway is not: it is one opening with two ends. Authored as a directed connection, an author can create `A→B` and `B→A` as two entries, and a solver that resolves both per tick would pass twice the intended gas through one opening and halve every equalization time. Recovering from that needs canonicalisation rules, a refusal for the second entry, and a tie-break for which one wins — an entire bug class manufactured by the representation. An undirected aggregate with two ends and no direction deletes the class instead of guarding it. A display-only link is synthesized for the diagram, and stays out of the solver: layout is presentation and never simulation input.

**Endpoints are compartments or Exterior vacuum (amended after #784).** Originally this decision refused the exterior to keep leaks and airlock cycles the only external-loss owners. That restriction is superseded: a partially open, scheduled opening to space needs the same authored pathway interface as an internal opening. Exactly one endpoint may instead be Exterior vacuum, represented by the reserved endpoint id `$exterior` (`StationExteriorAtmosphereId`); no actual compartment may claim that id. Two exterior endpoints and self-loops are refused. The boundary has fixed zero partial pressures, no inventory, no volume and no temperature: it is not an infinite or merely empty compartment. The solver takes the existing diffusion law's zero-pressure-boundary limit, not the finite pair equation with invented geometry. Every species lost is recorded separately in the compartment's cumulative `exteriorLostKg` and the pathway's signed flux; it is never added to internal diffusion, constant leakage or airlock losses. Existing leaks and cycles remain independent, additive mechanisms. A derived, inert Exterior diagram node displays the boundary without becoming a Station connection. The existing endpoint strings persist unchanged, so this adds no wire fields or schema bump; older readers refuse the unresolved endpoint rather than silently simulating a finite volume. Resource stores remain refused because a store is a mass ledger with a unit and a composition: it has no volume, no temperature and no pressure, so the equation has nothing to evaluate. A gas store is a bank account, not a volume of air. Self-loops are refused at validation rather than carried through the solver as a permanent no-op. Duplicate pathways between the same pair are allowed, because the conductance ratio between two compartments is fixed by the compartments and not by the pathway, so parallel pathways compose exactly additively — two half-square-metre pathways behave identically to one square-metre pathway, provably rather than approximately.

**Openness is runtime state, actuated through a sim-time-stamped command.** A pathway's openness may change during a run on command from a script or control layer. Because the value is constant within any one tick, the closed-form exchange stays exact at whatever openness the tick starts with, so actuation costs the integrator nothing. The command carries the simulation time at which it takes effect and resolves on the same occurrence rule every other scheduled thing in the model uses — occurrence time, then priority descending, then declaration order, last-applied winning. It is never indexed by tick count: "open at tick 100" is ten seconds at one cadence and twenty at another, so a tick-indexed command makes the same authored behaviour drift in time whenever the station step changes, and the path-equivalence tests fail on the actuation rather than the physics. Invalid commands — a value outside zero to one, a non-finite value, an unknown pathway — are refused by name and leave the value untouched, never clamped or defaulted, per the standing rule that incoherence is refused at the boundary. Each pathway records the last command that successfully set it, so every openness value in a run is traceable to a recorded actuation instead of a reconstruction of script execution order.

**Pathways report as a flux, not as a service.** Each pathway publishes a signed flow rate per gas and a cumulative net mass per gas, with a two-valued idle-or-active status. It deliberately does *not* carry the requested / actual / limiter fields the transfer vocabulary uses. Nothing asks for gas to move: the flow is wholly determined by state, so there is no request, no shortfall and no limiter to name. Forcing the service shape would make every pathway report that it received everything it asked for on every tick, which reads as a healthy service and reports nothing at all.

**Validation treats area and openness asymmetrically.** A pathway with zero openness is legitimate — a closed hatch that a command can open later. A pathway with zero area is permanently dead: its conductance is zero at every openness, so no command can ever make it pass anything, yet it holds an id, occupies the diagram, accepts commands that do nothing and reports idle forever. That is incoherent rather than merely imprudent, so area must be strictly positive while openness may be zero. There is no upper bound on area: the closed form lands on equilibrium monotonically no matter how absurd the geometry. A pathway-count ceiling exists in the spirit of the compartment ceiling, so a per-tick pass has a declared bound rather than an accidental one.

Reversing this decision means migrating the aggregate, re-deriving the directedness guard that the undirected shape makes unnecessary, and re-answering why a pathway reports service fields it has no requester for. That is why it is recorded rather than left implicit in the diff.
