# Station configuration documents

The Station Flow tab's New, Open, Save and Save As controls operate on a separate Configuration draft, not the World. Open replaces that draft after confirmation if it has unsaved changes; Apply settings in the Station Systems tab is still the only way to change the World. Saving does not pause or reset a simulation. Recent configuration paths are stored separately from recent Worlds.

A configuration document is YAML with `schemaVersion: 106` (schemas 96–105 remain readable; omitted fields use their defaults), the same `stationSystems` map written by the World serializer, and an optional `layout` map. Layout records view pan and zoom and node coordinates keyed by type, id and occurrence; it is never a simulation input. Missing layout is generated by the Flow view. Schema 106 persists `atmospherePathways` in declaration order, including `openFraction`, which is now a live parameter rather than a starting seed; unknown fields on those entries require conversion rather than being ignored. The `pathwayCommands` array was retired at 106. Reads are opt-in per field with no global unknown-key guard, so an older document that still carries `pathwayCommands` opens successfully but that array is **silently dropped** - its scheduled openings do not carry over, and nothing warns the author. Time-varying openness is served by the live mutating API instead. Older schemas carrying that array behave the same way. The `stationSystems` map is shared with World persistence, so configurations can be opened against other Worlds without changing their current settings. Invalid files leave the current draft and its undo history intact. In a configuration draft, any entry whose reference does not resolve - a Transfer's stores, a Conversion's endpoints, a radiator's reservoir, a chiller's loop, a generator's fuel, a crew's compartment, and so on - stays in the draft and appears as a broken (red) link on the canvas; the file still opens. Every other rule keeps its full strictness: an invalid value anywhere, including on a broken entry's own fields checked before the reference, refuses the file. Apply settings re-validates the whole configuration strictly, so broken wiring never reaches the World.

## Author a machine that warms a cabin

In Station Flow, place an **Electrolyzer** and **Atmosphere** (the cabin).
Wire the machine's water feed, hydrogen outlet, oxygen destination and electrical
supply as usual. Select the machine and enable **Thermal body** in its inspector;
set positive capacity (for example 100 kJ/K), starting temperature (40 C), and
positive sink-leg conductance (0.5 kW/K). Leave **Heat out** disconnected to cool
only through the cabin wall; the sink conductance is unused without a sink.

Place a **Thermal link**. Drag the machine's **Thermal body** face to **End A**
and the cabin's **Thermal links** face to **End B** (or select those typed entries
in the link inspector). Set a positive conductance, for example 1 kW/K. Invalid
endpoints, self-links and duplicate pairs are refused with a validation message.
A bodyless machine has no body face. Atmospheres and Reservoirs remain eligible
Thermal nodes alongside bodies; no mass crosses this wall.

Apply the draft and run. The machine readout shows casing temperature and signed
conducted kW; the wall shows signed A-to-B heat flow and cumulative energy, while
the cabin reports its conducted heat. Body capacity, starting temperature and
sink-leg conductance can be changed through the live-node inspector without
resetting current temperature; starting temperature becomes a reference value,
not a temperature command. Adding/removing the body changes topology and needs
Apply. Save the configuration to retain the body and typed link endpoints.

## Managed reference configurations

All bundled configurations are authored YAML files under `resources/station-systems/`,
registered as Willpower `StationConfiguration` resources in `resources/Resources.yaml`:

```yaml
    - type: StationConfiguration
      name: atmosphere-exterior-isolation
      location: station-systems/scenarios/atmosphere-exterior-isolation.yaml
```

`StationConfigurationResource` loads through the resource manager's data stream,
using the existing configuration parser. It retains settings and optional diagram
layout, plus the reference station's provenance, assumptions, qualification and
scenario expectations when present. Malformed resources fail loading with a
diagnostic; they are not silently omitted. The editor's **Configuration resource**
selector lists the manifest configurations, including atmosphere, water and
bioconversion examples. Selecting a configuration shows only its description and
optional reference metadata; it does not edit the draft and is available while
running. Plain examples display their leading YAML description comments.
**Load into draft** is a separate, paused-only action that copies the selected
settings and layout, supports configuration undo/redo, and does not apply to the
World or modify the shared Resource. Provenance, assumptions and scenario
expectations are expandable for the selected reference only.

The former `BundledStationReferenceSource.h.in`, `BundledStationScenariosSource.h.in`
and `BundledStationLongRunSource.h.in` wrappers and CMake YAML embedding are removed.
Changing configuration YAML no longer requires recompiling; it is read when the
resource is created. Physics smoke fixtures read the same authored files directly,
keeping the core test tier independent of the graphical/resource stack. The
embedded fallback for `lifecycle.lua` is unchanged: it is script code, not a
configuration document. User document Open/Save and recent-file handling remain
separate from the bundled resource catalogue.

## Adding Station entries

The Station Systems form uses one **Add entry** ComboBox in place of the separate
**Add store**, **Add transfer**, and other top-level Add buttons. Its entries are
grouped as Resources, Power, Conversion chain, Thermal, Biology, Water, Gas, and
Schedules, using the same type grouping as Flow placement. Choosing a type appends
one entry with the existing form defaults and an unused ID. Creation is paused-only,
changes only the draft, and supports configuration undo/redo. Entries at their
capacity limit remain visible but disabled. Row-specific additions (conversion
inputs/outputs, schedule segments, exchanges and maintenance requirements) remain
with their owning entry.

## Station step ratio

`stationSystems.systemsStepWorldTicks` is the positive integer number of World ticks per Station step. New settings default to `6` (10 Hz with the unchanged 60 Hz World), are limited to `1` through `60` (nominally 60 Hz–1 Hz), and are saved by both standalone configuration and World documents. The Station Systems draft exposes it as **Station step ratio (World ticks)**; applying a changed ratio follows the usual paused World structural-edit protocol, confirmation/reset, and document undo/redo path. Documents omitting the field retain legacy ratio 1; explicitly saved ratios are adopted unchanged. A value outside the range refuses the document or apply transactionally, naming the supplied value and allowed range.

In the Flow canvas, select a Store or Transfer and press Delete (or use **Delete selected node**) to remove it from the draft. When its authored connector links have referrers, the confirmation counts them before any change; cancelling keeps the draft and history unchanged. Confirmation clears every mapped reference and removes the node as one undoable change. Unlinked nodes need no confirmation. Deletion is unavailable in drafts containing entry families whose references have no core-owned mapping yet, even for an otherwise isolated Store or Transfer; other projected node types likewise cannot be deleted from Flow yet. Derived service nodes are never authored.

A placed Conversion arrives with one input and one output connector and can be grown with the `+` affordance below its port columns to four connectors per side; `−` removes the newest one, and neither affordance is offered past the limit, so the required floor of one input and one output can never be stripped. Every grown connector is a real connector: it takes drag-to-connect links and is judged by the same core constraint rules as fixed ones, writing its own flow of the conversion entry. Grown slots left unwired read as unused rather than missing. The Solar array is placeable and shows its implicit edge to the shared electrical pool; the pool itself renders as a derived service node - dashed, inert, with no draggable connectors and absent from the type combobox - and any link dropped on it, or click aimed at it, is refused with a reason naming it as derived. Placement, growth, shrinkage and wiring each commit one shared-history entry.

Saves use the same exclusive temporary-file and atomic-replacement writer as World documents; an unsuccessful write does not mark the draft saved.

## Material identity (#699)

Every Resource store offers **material identity** in both the form and Flow
inspector. Empty is visibly **Unclassified**, including in legacy documents.
An explicit ID is a stable, case-sensitive substance key: 1–64 ASCII characters,
starting with `a`–`z`, followed by lowercase letters or digits, with single
hyphens separating segments. For example: `water`, `oxygen`, `carbon-dioxide`,
`atmospheric-nitrogen`, `nutrient-nitrogen`, or `custom-feedstock-2`.
Spaces, uppercase letters, leading/trailing or repeated hyphens are refused,
not silently normalised. Custom materials need no separate registry.

The same ID identifies the same material across stores. It is independent of
the store ID, unit and compound composition. A compound's material
ID names the compound, not its constituent decomposition. No identity is guessed
from any of those fields: even a legacy store named `oxygen` in `kg` remains
unclassified without further evidence. The stored-material observation adapter
(#700) may resolve an omitted identity through unambiguous validated equipment
or transfer relationships, without filling in the authored field. Conflicting
evidence remains unclassified in observations. See [Station history](station-history.md)
for accounting coverage; intrinsic atmospheric and Biological inventories are
outside this stored-only slice.

Assignment changes only the Configuration draft until **Apply settings**.
Draft undo/redo, applied World history, Reset and structural restoration retain
identity. Both standalone and World documents save optional
`stationSystems.stores[].materialId` under schema 98; omission remains empty.
Invalid identity refuses configuration application or loading atomically. Reading
older documents does not dirty or rewrite them. Identity is observation metadata:
it does not change allocation, transfer compatibility or
chemistry, nor claim a complete material accounting boundary.

## One-off Scheduled transfers

Schema 99 adds Transfer `mode` (`Continuous` or `Scheduled`), `quantity`,
`firstOccurrenceSeconds`, and `recurrenceSeconds` (zero only). Older records
without mode retain Continuous behavior; older schema declarations with these
fields are refused. Both editors share the same draft fields and history;
incomplete Scheduled wiring can be saved and inspected but cannot be applied.
Only authored settings persist, never occurrence counters or moved quantities.
Scheduled connection design properties are informational and retained; these
lossless Non-physical events have no carrier or throughput controls.
See [Station systems](station-systems.md#one-off-scheduled-resource-transfers-690)
for execution order, reservation protection and forecast exclusions.

## Connection design properties

Click a connection curve to show **Connection properties** in the reserved
inspector column. This includes automatic electrical connections; their design
properties are editable even though their membership in the shared pool remains
automatic. Selecting a connection does not select or author a Derived service node.

Each connection has an independent physical connection type override and a
maximum throughput rating, where a flow rate is meaningful. Defaults are
**Automatic** and **1e12** in the displayed rate unit: kW for power/thermal flows,
the Resource store's native unit per second for material flows involving a Store,
or kg/s for other material flows. Ratings must be positive and finite. On physical
material, electrical, and thermal connections, the applied simulation caps
**connection input first**, then applies efficiency. Carrier overrides only change
presentation; they do not change enforcement, compatibility rules, link
cardinality, or automatic electrical pool membership. Non-physical relationships
do not offer a throughput field or a carrier override.

Every connection, including automatic power and non-physical relationships, also
has **Efficiency**, default **1.0**, in the inclusive range **[0, 1]**. For physical
connections it is the delivered fraction of accepted input: an input cap of
10 kg/s and efficiency 0.9 delivers at most 9 kg/s. Receiver demand is compensated
upstream within available supply and the input cap. At zero efficiency, actively
requested input is entirely lost; no demand means no flow. Non-finite and
out-of-range values are refused. Older connection entries without `efficiency`
load with 1.0.

Undelivered input is an explicit external connection loss, not returned to the
source or injected as waste into another reservoir. Produced heat blocked by an
input cap is retained at its source, separately from transmitted/lost heat, and
can enter the connection in later ticks. Non-physical relationships retain
informational ratings only; these include controls, cooling-service allocations,
ambient biological exchanges, circulation gates, schedules, delivery/waste-ejection
and airlock events, maintenance, and outages. Editing or saving properties still
changes only the Configuration draft until **Apply settings**. Applying non-default
physical throughput or efficiency makes the simplified scenario forecast explicitly
unavailable: it does not yet project transport constraints. Styling-only and
non-physical properties do not disable forecasts. See
[forecast scope](station-systems.md#scenario-forecast-420).

Heat engines enforce both thermal interfaces independently. **Thermal intake**
limits reservoir-side withdrawal; only delivered heat drives conversion, and
intake losses leave the Station. Engine intake telemetry measures delivered heat,
whereas the hot reservoir's extraction includes transport loss. **Rejection heat**
routes the machine's produced rejection through its own input cap and efficiency.
Heat blocked by that cap remains at the engine and drains in later ticks, even
while conversion is idle or tripped; it is never silently added to a reservoir.
The engine's rejection account measures produced heat, while the rejection
reservoir books only delivered heat. Sink-temperature protection still trips the
whole conversion, preventing new intake, generation, and rejection production.

Carrier overrides and ratings are sparse entries in `stationSystems.connections`,
not layout. For example, the input connection of a Transfer named `move` fed by
Store `a` can carry:

```yaml
connections:
  - ownerType: Transfer
    ownerId: move
    reference: Source
    relation: Source
    peerType: Store
    peerId: a
    physicalType: Liquid pipe
    maximumThroughput: 1000000000000
    efficiency: 1.0
```

Omitting an entry uses that connection's defaults without materialising a saved
entry. **Reset connection properties** restores those defaults. Properties travel
through standalone configuration and World save/load, and through configuration
undo/redo. **Rename selected node** preserves them at either endpoint;
disconnecting a reference, shrinking away its port, deleting an endpoint, or
rewiring it removes the old instance's properties. Reconnecting starts with
defaults; undoing a disconnect restores its properties along with the connection.
Schema 97 protects these authored fields from silent loss in older readers.
