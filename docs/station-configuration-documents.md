# Station configuration documents

The Station Flow tab's New, Open, Save and Save As controls operate on a separate Configuration draft, not the World. Open replaces that draft after confirmation if it has unsaved changes; Apply settings in the Station Systems tab is still the only way to change the World. Saving does not pause or reset a simulation. Recent configuration paths are stored separately from recent Worlds.

A configuration document is YAML with `schemaVersion: 96`, the same `stationSystems` map written by the World serializer, and an optional `layout` map. Layout records view pan and zoom and node coordinates keyed by type, id and occurrence; it is never a simulation input. Missing layout is generated by the Flow view. The `stationSystems` map is shared with World persistence, so configurations can be opened against other Worlds without changing their current settings. Invalid files leave the current draft and its undo history intact. Unresolved Store references in Transfers remain in the draft and appear as broken links on the canvas.

Saves use the same exclusive temporary-file and atomic-replacement writer as World documents; an unsuccessful write does not mark the draft saved.
