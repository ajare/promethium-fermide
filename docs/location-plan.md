# Location plan

Select a Room, Corridor, or Facade in the World canvas and choose **Location plan** in Selection. The plan opens at the clicked World Level. A single reusable window stays pinned to that Location even when ordinary Selection changes; choosing the button for another Location explicitly retargets it. The Level selector lists World Levels, including the Location's vertical offset, not Location-local supporting-Level offsets.

The grid's horizontal labels are World X, including the Location's horizontal offset. It shows integer Local depths 0–3 at minimum, with 0 at the bottom. Contents on the displayed supporting Level expand the range to retain one row beyond the greatest instance or resolved Furniture vertex depth, including catalogue offsets. The range never automatically shrinks after movement or deletion (or when changing Level). Local depth describes ordering, not physical distance, World height, or Layer. The Location's Layer is shown separately.

World content is recorded in `WorldDrawList`, clipped to the plan viewport and rendered by MPP into a dedicated offscreen texture. It never overwrites the main World canvas texture before ImGui composites both images.

Closing and reopening starts a fresh view at the selected Level. History reconstruction refreshes the view only when the same World still has a matching authored Location at its pinned index (type, name, Layer, position, and extent). World replacement, target deletion, and mismatching reconstructed Locations close the transient view rather than blindly rebinding a reused Sector index. Opening again selects the current World-owned Location. The plan adds no document data or persistence schema.

Furniture belonging to the pinned Location and displayed supporting Level appears as labelled horizontal-footprint rectangles, one row at the instance Local depth. Fractional X, negative tile offsets, and the full multi-tile artwork width are preserved; artwork height does not become physical depth. Each Furniture usable point is an outline circle at its authored X on the instance's Local-depth row. Matching gold lines connect the circle to its live usable Marker vertex at each incident route depth. The circle stays inside the Furniture's footprint row while routing vertices sit on integer-depth grid lines. Circles and connectors use the same gold as usable vertices. These connectors are presentation guides, not new routing edges. Unsupported Floor spans are shaded, including gaps in upper-Level Walkways. Shading is guidance only: existing Furniture validation remains authoritative.

The live routing graph is overlaid with cyan edges: lines are actual edges wholly within the pinned Location and displayed Level, positioned exactly on the grid line at each edge's resolved integer Local depth (0, 1, 2, …), not in the middle of a row. Depth labels align with those grid lines. Graph edges and usable-point connectors are 3 pixels thick, compared with 1-pixel grid lines, and all graph edges/vertices are drawn after the Furniture quads so they remain visible. The graph has an 8-pixel drawing margin beyond the grid boundary, keeping depth-0 strokes and boundary vertex dots fully visible while respecting the outer viewport/caller clip. Furniture, previews, and placement coordinates retain their original grid bounds. Radius-3 dots show every vertex on that Level: usable Marker vertices are gold, authored Furniture external ports (`external: true`) are green, and other vertices are cyan. Usable external ports remain gold. External ports and usable points are painted after ordinary vertices so coincident floor anchors cannot hide their colours; inferred anchors are not themselves external ports. A vertex has no intrinsic Local depth, so it appears once at each incident edge depth; isolated vertices appear at depth 0. Repeated dots at different depths represent the same vertex, not additional authored points. Thin grey dotted vertical guides join consecutive depth projections of each vertex behind its glyphs. These guides indicate shared graph identity, not routing edges or extra connectivity; distinct vertices are never joined merely because they share a name or World position. Connections to other Locations, Layers, or Levels are not projected into this single-Level view. The overlay refreshes from the current graph after edits and history reconstruction, remains visible without a Furniture catalogue, and does not infer links from overlapping footprints. Graph depths also expand the displayed range. Usable-point connectors resolve the owned Marker's stable identity, so overlapping or renamed points cannot be linked to the wrong vertex.

The World panel's **Furniture** header contains only catalogue selection. Choose **Select Furniture catalogue...** to open a native file picker for a `.furniture.lua` file beside the saved World. Cancellation or invalid selections leave the document unchanged; successful catalogue changes use ordinary document history.

While the plan is open, the World palette gains a third row of definitions from the currently attached Furniture catalogue, independent of focus/hover. Large catalogues use **Next page** to keep every definition accessible within the tray. Long labels are clipped to their slots and shown in full in hover tooltips. Without a catalogue, the row displays a diagnostic rather than stale definitions.

Drag a definition into the plan grid to place Furniture on its pinned Location and selected Level. New placements always snap to whole World-cell X and integer Local depth, even with Shift held. Green/red footprint previews use ordinary Furniture validation without changing the World. Releasing a valid candidate creates one normal, uniquely named instance (for example Chair, Chair 2) and one undoable document edit. Unsupported Floor, boundary crossings, overlap, other UI surfaces, and stale catalogue/Location/World targets cannot receive a placement. Escape/right-click cancels a drag. Save/reopen and undo/redo use ordinary Furniture persistence and retain owned Marker identities.

Hover a graph vertex to show its name in a tooltip and use the hand cursor. Vertex hover takes precedence over Furniture footprints and follows the graph's paint order: usable vertices first, then external ports, then ordinary points at coincident positions. Usable vertices show their current Marker names; authored routing-only vertices show the Furniture instance name and vertex key. Hovering a Furniture footprint without a vertex also uses the hand cursor. Depth-0 vertices remain hoverable in the graph margin. Hover feedback never changes selection or document history.

Click an existing footprint to select its instance without changing the pinned plan. The selected footprint has a gold outline. Left-drag previews movement with whole-cell X snapping; holding Shift allows fractional X, and changing Shift immediately updates the preview. Local depth remains a non-negative integer. Movement keeps the same Location and supporting Level. A valid release inside the grid commits exactly one undoable edit and preserves instance and owned Marker identities and names; invalid or cancelled releases change nothing. Reconstruction, deletion, or catalogue replacement invalidate stale selections and gestures. Pre-existing Furniture can be moved without palette placement.

Choose **Delete selected Furniture** to remove the selected instance on the pinned Location and displayed Level. The plan uses existing reference-safe deletion: a refused operation displays its diagnostic and preserves contents, selection, references, and history. Successful deletion clears selection and gestures and commits one undoable edit. Undo restores the instance and owned Marker identities; redo removes them again without retargeting the plan or shrinking its expanded depth range. Selection of Furniture outside the displayed plan cannot be deleted through this control.
